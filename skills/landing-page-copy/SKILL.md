# Landing Page Copy

## Purpose

Write landing-page copy that moves a specific visitor from their current belief to the belief required for the next action.

Do not begin by filling a generic page template. First determine what the page is supposed to accomplish.

## Core principle

A landing page is a belief-change system.

Before drafting, answer:

1. Who is this page for?
2. What does that visitor currently believe?
3. What do they need to believe before acting?
4. What proof would make that belief credible?
5. What is the lowest-friction useful next action?

The copy, section order, proof, and CTA must all support that belief change.

## Workflow

### 1. Diagnose the page job

Write a one-sentence diagnosis:

> This page exists to help `[audience]` believe `[required belief]` so they will `[next action]`.

Choose the primary website type:

- Product-led.
- Enterprise infrastructure.
- Mission-led.
- Corporate reputation.
- Consumer ecosystem.
- Regulated trust.
- Marketplace platform.
- Recruitment-led.
- High-risk adoption.
- Category creation.

### 2. Extract the strategic message

Define:

- Core promise.
- Mechanism.
- Differentiator.
- Proof.
- Main objection.
- Primary CTA.

Use plain language. Avoid using the product category as the promise unless the category itself is valuable to the audience.

### 3. Define the belief sequence

Choose the shortest sequence that resolves the visitor's concerns.

Common sequences:

- Product-led: desired output → ease → capability → examples → start.
- Enterprise: business outcome → platform mechanism → technical credibility → customer proof → demo.
- Mission-led: future → why it matters → mechanism → evidence → participation.
- Regulated: opportunity → control → compliance → institutional proof → consultation.
- High-risk: emotional reassurance → simple mechanism → quantified evidence → real-world proof → trial.
- Recruitment: meaningful mission → hard problem → focused company → team identity → apply.

Do not add sections that do not advance the sequence.

### 4. Build the page architecture

For every section, define:

```text
Section:
Job:
Visitor question:
Message:
Proof:
CTA:
```

A typical architecture is:

1. Hero.
2. Immediate clarification.
3. Main outcomes.
4. Mechanism.
5. Proof.
6. Objection handling.
7. Audience or use-case routing.
8. Conversion section.

Reorder these for the selected website type.

### 5. Write the hero

The hero must answer:

- What is this?
- Why should I care?
- What can I do next?

Use:

```text
Eyebrow: optional category or audience context
Headline: one clear promise or future state
Subheadline: mechanism, scope, or qualification
Primary CTA: lowest-friction useful action
Secondary CTA: proof or lower-commitment path, when needed
```

Prefer one idea over a list of features. Lead with the customer change, not internal company language. Avoid unsupported superlatives.

### 6. Translate features into benefits

Use this chain:

> Feature → capability → workflow change → measurable outcome → human or business benefit.

Never stop at the feature name.

### 7. Select proof deliberately

Match proof to the audience's risk:

- Can it work? Demonstration or technical explanation.
- Will it work for a company like mine? Relevant customer outcomes.
- Is it safe? Safety metrics, audits, policies, and incident handling.
- Is it credible? Customers, partners, operating history, and governance.
- Can it scale? Volume, uptime, latency, capacity, and geographic coverage.
- Is the mission real? Milestones, research, operating commitments, and team.

Prefer specific evidence over adjectives. Never invent metrics, customer names, awards, or outcomes.

### 8. Design CTAs by readiness

- Curious: Explore, watch the film, see how it works.
- Ready to try: Start free, download, start designing.
- Needs validation: View customer stories, read the report, see the demo.
- Technical evaluator: Read documentation, view API, explore integrations.
- Enterprise buyer: Book a demo, contact sales, talk to an expert.
- Location constrained: Check availability, enter postcode, sign up for updates.
- Candidate: Join us, view roles, apply.

Use one dominant CTA per page and contextual secondary CTAs.

### 9. Handle objections

Identify the highest-value objection, then answer it with evidence. Common objections include difficulty, price, safety, compliance, scalability, compatibility, availability, disruption, immaturity, and relevance.

### 10. Edit for clarity

Run strategy, audience, specificity, hierarchy, conversion, voice, and compression passes.

## Quality bar

A strong page has one primary strategic job, makes the customer change obvious, translates features into outcomes, uses proof that addresses the actual risk, gives visitors a clear next action, and feels like one argument rather than a collection of sections.
